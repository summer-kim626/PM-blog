## 2. 개요

블로그 글을 쓰고 나면 SNS 홍보용 요약과 카드뉴스를 **따로 다시 만들어야 해서** 홍보를 자주 건너뛰게 된다.
이 프로젝트는 `posts/`에 새 글을 올리면 **GitHub Actions가 AI(Gemini 3.8 Flash)로 글을 요약하고, 인스타그램 카드뉴스(1080×1350, 5~7장) 초안을 자동으로 만들어** 저장소에 커밋한다.
관리자는 **관리자 페이지(`/admin`)** 에서 생성 상태를 확인하고, 카드와 캡션을 내려받아 올리기만 하면 된다. 목표는 **"글쓰기 → 홍보" 사이의 손작업을 없애는 것**이다.

## 3. 문제 정의

> **1인 블로그 운영자는 글을 쓴 뒤 홍보용 카드뉴스를 따로 만들 시간이 없어, 글을 올려도 SNS 홍보를 건너뛰고 유입 기회를 놓친다.**

### 3.1 현재 상황 (ASIS)

- 글 1편을 쓰고 나면 **요약 → Canva로 카드 제작 → 캡션 작성**을 다시 해야 해서 **추가로 1시간 이상**이 든다.
- 그 시간이 부담스러워 홍보를 자주 건너뛰고, 그 결과 블로그 유입이 늘지 않는다.
- 범용 AI 챗봇이나 Canva 템플릿도 매번 복사·붙여넣기와 편집이 필요하고 블로그와 연결되지 않는다.

### 3.2 문제와 타깃

| 문제                                                          | 타깃        |
| ------------------------------------------------------------- | ----------- |
| 글을 카드뉴스로 옮길 때 요약·디자인·카피 작성이 매번 반복된다 | 관리자(나)  |
| 홍보가 귀찮아 SNS 공유를 건너뛰고, 그래서 유입이 늘지 않는다  | 관리자(나)  |
| 글이 길면 독자가 핵심을 빨리 파악하기 어렵다                  | 블로그 독자 |

- **1순위 — 관리자(나):** 주 1~2회 PM 학습 글을 쓰는 취업 준비생. 글을 쓴 뒤 홍보 작업에 쓸 시간이 부족하다.
- **2순위 — 독자:** 출퇴근길에 모바일로 PM 콘텐츠를 훑어보는 주니어 기획자.

### 3.3 환경 분석 요약

| 구분 | 내용                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------- |
| 강점 | 정적 HTML 블로그와 GitHub Actions 자동화(날씨 봇) 운영 경험이 있고, 글이 HTML이라 AI 입력으로 쓰기 쉽다 |
| 약점 | 1인 운영이라 시간이 적고, SNS 운영 경험과 유입 채널이 부족하다                                          |
| 기회 | 인스타그램에서 카드뉴스형 정보 콘텐츠가 많이 소비되고, 무료로 쓸 수 있는 LLM이 있다                     |
| 위협 | AI 문구의 사실 오류가 신뢰를 해칠 수 있고, 무료 모델은 호출 한도·정책이 바뀔 수 있다                    |

## 4. 해결 방향

### 4.1 범위 (MoSCoW)

| 범위   | 항목                                                                                |
| ------ | ----------------------------------------------------------------------------------- |
| Must   | 새 글 자동 요약 + 카드뉴스 PNG 생성(F1~F5), 관리자 페이지에서 상태 확인·다운로드(F7) |
| Should | 글 상단 AI 3줄 요약(F6), 캡션·해시태그 생성·복사, 관리자 페이지에서 재생성 요청     |
| Could  | 카드 디자인 테마 선택, AI 호출 없이 PNG만 다시 그리기                               |
| Won't  | 인스타그램 자동 업로드 (비즈니스 계정·API 심사가 필요해 기한 안에 불가, D-003)      |

### 4.2 기능 요구사항

| ID  | 우선 | 기능             | 설명                                                                                                                          | 완료 기준                                                         |
| --- | ---- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |

| F6  | Should | 글 상단 요약   | 글 페이지가 `summary.json`을 불러와 상단에 3줄 요약 + "AI 초안" 배지 표시                                                     | 파일이 없거나 불러오지 못하면 요약 영역을 숨김                    |
| F7  | Must | 관리자 페이지    | `/admin` 표에서 글별 생성 유무 확인, 미리보기, ZIP 다운로드, 재생성 요청(4.3)                                                  | 모든 글이 표에 있고, 완료된 글의 카드 전 장이 ZIP으로 받아짐      |

### 4.3 화면 구성

**① 관리자 페이지 `/admin` (`admin/index.html`, D-008)**

글 목록(`index.html` `posts` 배열)과 생성 상태(`data/cardnews/index.json`)를 합쳐 **글 1편 = 표 1행**으로 보여준다.

| 글 제목 | AI 요약(카드뉴스) 생성 유무 | 미리보기 | 다운로드 | 재생성 |
| --- | --- | --- | --- | --- |
| 글 페이지 링크 | 상태 칩 + 생성 시각 | 카드·요약·캡션 팝업 | ZIP 1개 | Actions 수동 실행 |

- **생성 유무(상태 칩):** `미생성`(기록 없음) · `완료` · `경고`(완료됐지만 글자 넘침 등 경고 있음, 마우스를 올리면 내용 표시) · `실패`(오류 메시지 표시).
- **미리보기:** 팝업에 카드 축소 미리보기(`template.html?scale=0.35` 재사용), 3줄 요약, 캡션·해시태그 [복사] 버튼, 장별 PNG 저장을 보여준다.
- **다운로드:** 카드 PNG 전 장 + `caption.txt`(캡션·해시태그)를 `<slug>-cardnews.zip` 하나로 내려받는다(브라우저에서 JSZip으로 묶음).
- **재생성:** 해당 글의 요약·카드 문구·캡션·PNG를 AI로 **모두 다시 생성해 덮어쓴다**(글 본문은 그대로). 버튼은 GitHub Actions 수동 실행(`workflow_dispatch`, slug 입력) 화면을 열며, 브라우저는 API 키나 GitHub 토큰을 다루지 않는다.
- **상태별 버튼:** `미생성`·`실패`는 미리보기·다운로드를 비활성화하고 재생성 버튼 이름을 [생성]으로 바꾼다.
- **접근:** 별도 로그인 없음(공개 데이터만 읽고, 생성은 GitHub 로그인이 필요). 검색 노출을 막도록 `noindex`를 넣고 블로그 메뉴에는 링크하지 않는다.

**② 글 페이지 상단 요약 (F6):** 제목 아래 박스에 3줄 요약을 넣고 우측 상단에 "AI 초안" 배지를 단다. 색은 기존 `:root` 토큰(`--accent-soft`, `--line`)만 쓴다.

**유저 플로우:** 글 작성 → `posts/`에 푸시 → (Actions 5분 이내) → `/admin`에서 `완료` 확인 → 미리보기 검토 → PNG·캡션 다운로드 → 인스타그램에 직접 업로드

### 4.4 기술 구성

| 항목       | 내용                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------- |
| AI 모델    | Google `gemini-3.8-flash` (무료 등급, D-007). 키는 GitHub Secret `GEMINI_API_KEY`               |
| 실행 환경  | GitHub Actions (`.github/workflows/cardnews.yml`), 트리거: `push`(paths `posts/**`) + `workflow_dispatch` |
| 렌더링     | 헤드리스 브라우저로 `template.html?capture` 캡처. 글꼴 CDN 때문에 인터넷 연결 필요              |
| 블로그     | 정적 HTML. `summary.json`을 `fetch`로 읽으므로 배포 주소(HTTP)에서 동작, `file://`에서는 동작 안 함 |

## 5. 성공 기준 (OKR)

- **O:** 글을 올리면 바로 홍보까지 이어지는 블로그 운영 흐름을 만든다
- **KR1:** 글 1편당 홍보 콘텐츠 제작 시간 60분 → 10분 이하 (관리자 페이지 확인부터 업로드 준비 완료까지 직접 측정)
- **KR2:** 발행 글 중 카드뉴스가 `완료`·`경고` 상태인 비율 100% (`index.json` 기준)
- **KR3:** 문구 수정 1회 이하로 쓴 카드뉴스 비율 70% 이상 (게시 전 고친 카드 장 수를 직접 기록)

## 6. 주요 리스크

| 리스크                     | 대응                                                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| AI 요약의 사실 오류        | "AI 초안" 표기, 프롬프트에 "본문에 없는 내용 금지" 규칙, 관리자가 게시 전 검토            |
