## **2\. 개요**

블로그 글을 쓰고 나면 SNS 홍보용 요약과 카드뉴스를 **따로 다시 만들어야 해서**, 글 1편당 추가로 1시간 이상이 들고 홍보를 자주 건너뛰게 된다.
이 프로젝트는 `posts/`에 새 글을 올리면 **GitHub Actions가 AI로 글을 요약하고, 인스타그램 카드뉴스(1080×1350, 5~7장) 초안을 자동으로 만들어** 블로그와 저장소에 올려준다.
관리자는 생성된 카드를 검토하고 내려받아 올리기만 하면 되므로, **"글쓰기 → 홍보" 사이의 손작업을 없애는 것**이 목표다.

## **3\. 문제**

### **3.1 데스크리서치**

#### 3.1.1 SWOT 분석

| 강점 (S) | 약점 (W) |
| --- | --- |
| 정적 블로그 + GitHub Actions 자동화(날씨) 경험이 이미 있음 | 1인 운영이라 글쓰기 외 작업에 쓸 시간이 적음 |
| 글이 HTML 파일로 정리돼 있어 AI 입력으로 쓰기 쉬움 | 블로그 유입 채널이 적고 SNS 운영 경험이 적음 |
| **기회 (O)** | **위협 (T)** |
| 인스타그램은 카드뉴스형 정보 콘텐츠 소비가 활발함 | AI 생성 문구의 사실 오류·어색함이 신뢰를 떨어뜨릴 수 있음 |
| LLM으로 요약·카피 작성을 자동화하는 비용이 낮아짐 | 플랫폼 정책 변화로 자동 업로드가 막힐 수 있음 |

#### 3.1.2 3C 분석

- **Customer (나 = 1인 블로그 운영자):** 글은 쓰지만 홍보 콘텐츠를 만들 여력이 없다.
- **Company (PM-blog):** 정적 HTML 블로그, GTM 설치, Actions + Secrets 운영 구조를 이미 갖춤.
- **Competitor (대체재):** Canva 템플릿 수작업, 범용 AI 챗봇에 글을 복사해 요약 요청 → 매번 복붙·편집이 필요하고 블로그와 연결되지 않음.

#### 3.4.1 우선 순위 결정 (MoSCoW)

| 구분 | 항목 |
| --- | --- |

## **4\. 해결 방안**

### **4.1 솔루션 정의**
`posts/`에 새 글이 푸시되면 AI가 글을 요약하고 카드뉴스 초안 이미지·캡션·해시태그를 자동 생성해, **관리자가 검토 후 바로 올릴 수 있는 상태**로 만든다.

### **4.2 ASIS / TOBE**

| 항목 | ASIS | TOBE |
| --- | --- | --- |
| 컨셉 | 글쓰기와 홍보가 분리된 수작업 | 글 발행이 곧 홍보 초안 생성 |
| 타겟 | — | 1순위 관리자(나), 2순위 블로그 독자 |
| 비즈니스 모델 | 없음 (개인 블로그) | 무료 운영, API 비용 글 1편당 수십 원 수준 목표 [확인 필요] |
| 기능 | 직접 요약 → Canva 제작 → 캡션 작성 | 푸시 → 자동 생성 → 검토 → 다운로드 |
| 디자인 | — | 블로그 톤(오렌지 액센트)과 통일된 카드 템플릿 |

### **4.3 예상 성과 (OKR)**
- **O:** 글을 올리는 즉시 홍보까지 이어지는 블로그 운영 흐름을 만든다
- **KR1:** 글 1편당 홍보 콘텐츠 제작 시간 60분 → 10분 이하
- **KR2:** 발행 글 중 카드뉴스가 생성되는 비율 100%
- **KR3:** 생성된 카드뉴스를 수정 없이(또는 1회 이하 수정으로) 쓰는 비율 70% 이상

## **5\. 가설 및 지표**

### **5.1 핵심 지표 (Key Metrics)**

| 가설 | 측정 지표 |
| --- | --- |
| 초안이 자동으로 있으면 홍보를 건너뛰지 않는다 | 발행 글 대비 SNS 게시 비율 |
| AI 요약이 있으면 독자가 글을 더 끝까지 읽는다 | 요약 영역 노출 후 스크롤 깊이·체류 시간 (GTM 이벤트) |
| 카드뉴스 품질이 쓸 만하다 | 수정 없이 사용한 카드 비율 |

### **5.2 고객 정의 (Persona)**
- **1순위 — 관리자(나):** 주 1~2회 PM 학습 글을 쓰는 취업 준비생. 글쓰기 이후 홍보 작업에 쓸 시간이 부족하다.
- **2순위 — 독자:** 출퇴근 중 모바일로 PM 콘텐츠를 훑어보는 주니어 기획자.

### **5.3 마케팅 메시지**
- 핵심 카피: **"글만 쓰세요. 카드뉴스는 AI가 만듭니다."**
- 용어 가이드: "AI 초안"(완성본이 아님을 명시), "3줄 요약", "카드뉴스"

## **6\. 기능적 요구사항**

| ID | 기능 | 설명 |
| --- | --- | --- |
| F1 | 새 글 감지 | `posts/*.html` 추가·수정 푸시 시 Actions 실행 |
| F2 | 본문 추출 | HTML에서 제목·본문 텍스트만 추출 |
| F3 | AI 요약 | 3줄 요약 + 카드별 문구(표지·핵심 3~5장·CTA) + 캡션·해시태그를 JSON으로 생성 |
| F4 | 카드 이미지 렌더링 | HTML 카드 템플릿에 문구를 넣고 1080×1350 PNG로 캡처 |
| F5 | 결과 저장 | `data/cardnews/<slug>/`에 JSON·PNG 커밋 |
| F6 | 블로그 노출 | 글 상단 3줄 요약, 카드뉴스 미리보기·다운로드 페이지 |

**유즈케이스:** 관리자가 새 글 HTML을 푸시 → Actions가 F2~F5 실행 → 몇 분 뒤 블로그 카드뉴스 페이지에서 결과 확인 → PNG·캡션을 내려받아 인스타그램에 직접 게시

## **7\. 비기능적 요구사항**
- **보안:** AI API 키는 GitHub Secrets에만 보관, 브라우저 코드에 노출하지 않음
- **성능:** 글 푸시 후 5분 이내 카드뉴스 생성 완료, 블로그 페이지 로드 2초 이내
- **안정성:** AI 응답이 JSON 형식에 맞지 않으면 1회 재시도 후 실패 로그를 남기고 기존 글 배포는 막지 않음
- **비용:** 이미 생성된 글은 본문이 바뀌었을 때만 다시 생성
