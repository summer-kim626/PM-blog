## 2. 개요

블로그 글을 쓰고 나면 SNS 홍보용 요약과 카드뉴스를 **따로 다시 만들어야 해서** 홍보를 자주 건너뛰게 된다.
이 프로젝트는 관리자가 **관리자 페이지(`/admin`)에서 글의 [생성] 버튼을 누르면, 브라우저가 AI(Claude Opus 5.5)로 글을 요약하고 인스타그램 카드뉴스(1080×1350, 5~7장) 초안을 만들어** 저장소에 커밋한다.
관리자는 같은 화면에서 진행 단계와 결과를 바로 확인하고, 카드와 캡션을 내려받아 올리기만 하면 된다. 목표는 **"글쓰기 → 홍보" 사이의 손작업을 없애는 것**이다.

## 3. 문제 정의

> **1인 블로그 운영자는 글을 쓴 뒤 홍보용 카드뉴스를 따로 만들 시간이 없어, 글을 올려도 SNS 홍보를 건너뛰고 유입 기회를 놓친다.**

### 3.1 현재 상황 (ASIS)

- 글 1편을 쓰고 나면 **요약 → Canva로 카드 제작 → 캡션 작성**을 다시 해야 해서 **추가로 1시간 이상**이 든다.
- 그 시간이 부담스러워 홍보를 자주 건너뛰고, 그 결과 블로그 유입이 늘지 않는다.
- 범용 AI 챗봇이나 Canva 템플릿도 매번 복사·붙여넣기와 편집이 필요하고 블로그와 연결되지 않는다.

### 3.2 문제와 타깃

| 문제                                                          | 타깃        |
| ------------------------------------------------------------- | ----------- |
| 글을 카드뉴스로 옮길 때 요약·디자인·카피 작성이 매번 반복된다 | 관리자(나)  |
| 홍보가 귀찮아 SNS 공유를 건너뛰고, 그래서 유입이 늘지 않는다  | 관리자(나)  |
| 글이 길면 독자가 핵심을 빨리 파악하기 어렵다                  | 블로그 독자 |

- **1순위 — 관리자(나):** 주 1~2회 PM 학습 글을 쓰는 취업 준비생. 글을 쓴 뒤 홍보 작업에 쓸 시간이 부족하다.
- **2순위 — 독자:** 출퇴근길에 모바일로 PM 콘텐츠를 훑어보는 주니어 기획자.

### 3.3 환경 분석 요약

| 구분 | 내용                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------- |
| 강점 | 정적 HTML 블로그와 GitHub Actions 자동화(날씨 봇) 운영 경험이 있고, 글이 HTML이라 AI 입력으로 쓰기 쉽다 |
| 약점 | 1인 운영이라 시간이 적고, SNS 운영 경험과 유입 채널이 부족하다                                          |
| 기회 | 인스타그램에서 카드뉴스형 정보 콘텐츠가 많이 소비되고, LLM API로 요약·카피를 몇 초 만에 만들 수 있다      |
| 위협 | AI 문구의 사실 오류가 신뢰를 해칠 수 있고, API 호출마다 요금이 들며 키가 새면 요금이 청구될 수 있다     |

## 4. 해결 방향

### 4.1 범위 (MoSCoW)

| 범위   | 항목                                                                                |
| ------ | ----------------------------------------------------------------------------------- |
| Must   | 관리자 페이지에서 요약 + 카드뉴스 PNG 생성·저장(F1~F5), 상태 확인·다운로드(F7)       |
| Should | 글 상단 AI 3줄 요약(F6), 캡션·해시태그 생성·복사, 생성 진행 단계 표시              |
| Could  | 카드 디자인 테마 선택, AI 호출 없이 PNG만 다시 그리기                               |
| Won't  | 인스타그램 자동 업로드 (비즈니스 계정·API 심사가 필요해 기한 안에 불가), 새 글 푸시 시 자동 생성 (키를 서버에 두지 않는 방식으로 바꾸며 제외) |

| F1  | Must | 생성 실행       | `/admin`의 글별 [생성]·[재생성] 버튼으로 실행. 키는 관리자가 입력하고 그 탭에만 보관. 한 번에 글 1편 | 클릭 후 3분 안에 4단계(추출·AI·렌더링·커밋) 완료 표시, 실패 시 실패 단계와 원인 표시 |

### 4.3 화면 구성

**① 관리자 페이지 `/admin` (`admin/index.html`)**

글 목록(`index.html` `posts` 배열)과 생성 상태(`data/cardnews/index.json`)를 합쳐 **글 1편 = 표 1행**으로 보여준다.

| 글 제목 | AI 요약(카드뉴스) 생성 유무 | 미리보기 | 다운로드 | 재생성 |
| --- | --- | --- | --- | --- |
| 글 페이지 링크 | 상태 칩 + 생성 시각 | 카드·요약·캡션 팝업 | ZIP 1개 | 브라우저에서 바로 생성 |

- **생성 유무(상태 칩):** `미생성`(기록 없음) · `완료` · `경고`(완료됐지만 글자 넘침 등 경고 있음, 마우스를 올리면 내용 표시) · `실패`(오류 메시지 표시).
- **미리보기:** 팝업에 실제 생성된 카드 PNG, 3줄 요약, 캡션·해시태그 [복사] 버튼, 장별 PNG 저장을 보여준다.
- **다운로드:** 카드 PNG 전 장 + `caption.txt`(캡션·해시태그)를 `<slug>-cardnews.zip` 하나로 내려받는다(브라우저에서 JSZip으로 묶음).
- **API 키:** 표 위 칸에 Claude API 키와 GitHub 토큰(이 저장소만, Contents 쓰기)을 넣는다. 이 탭에만 보관되고 탭을 닫으면 지워진다. 토큰이 없으면 저장소에 올리지 않고 미리보기·ZIP만 된다.
- **생성·재생성:** 해당 글의 요약·카드 문구·캡션·PNG를 AI로 **모두 다시 생성해 덮어쓴다**(글 본문은 그대로). 팝업에 4단계 진행 상황을 보여주고, 끝나면 결과 미리보기로 바뀐다. 커밋 후 블로그 반영까지 1~2분 걸리지만 그 탭에서는 바로 볼 수 있다.
- **상태별 버튼:** `미생성`은 미리보기·다운로드를 비활성화하고 버튼 이름을 [생성]으로 바꾼다. `실패`라도 이전에 만든 결과가 남아 있으면 그 결과를 미리보기·다운로드할 수 있다.
- **접근:** 홈 왼쪽 사이드바의 [관리자] 링크로 들어간다. 들어가면 인증 번호 4자리를 먼저 묻고, 맞으면 그 탭에서는 다시 묻지 않는다(5번 틀리면 30초 대기). 정적 페이지라 화면 가림용이며, 생성에는 여전히 관리자의 Claude 키·GitHub 토큰이 필요하다. 검색 노출을 막도록 `noindex`를 넣는다.

**② 글 페이지 상단 요약 (F6):** 제목 아래 박스에 3줄 요약을 넣고 우측 상단에 "AI 초안" 배지를 단다. 색은 기존 `:root` 토큰(`--accent-soft`, `--line`)만 쓴다.

**유저 플로우:** 글 작성 → `posts/`에 푸시 → `/admin`에서 키 입력 → [생성] → 진행 단계 확인(1~2분) → 미리보기 검토 → PNG·캡션 다운로드 → 인스타그램에 직접 업로드

### 4.4 기술 구성

| 항목       | 내용                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------- |
| AI 모델    | Anthropic `claude-opus-5-5`(공식 SDK `@anthropic-ai/sdk` 1.7.0), 과부하·시간 초과 시 `claude-sonnet-5-5`로 대체. 키는 관리자가 입력 |
| 실행 환경  | 관리자의 브라우저(`admin/index.html`). 로컬 Node 스크립트(`npm run cardnews`)도 같은 모듈(`parse`·`ai`·`validate`)을 씀 |
| 렌더링     | 브라우저: `template.html?capture`를 html-to-image로 캡처. Node: 헤드리스 Chrome. 글꼴 CDN 때문에 인터넷 연결 필요 |
| 저장       | GitHub Git Data API로 커밋 1개. 이 저장소만 고른 fine-grained 토큰 사용                         |
| 블로그     | 정적 HTML. `summary.json`을 `fetch`로 읽으므로 배포 주소(HTTP)에서 동작, `file://`에서는 동작 안 함 |

## 5. 성공 기준 (OKR)

- **O:** 글을 올리면 바로 홍보까지 이어지는 블로그 운영 흐름을 만든다
- **KR1:** 글 1편당 홍보 콘텐츠 제작 시간 60분 → 10분 이하 (관리자 페이지 확인부터 업로드 준비 완료까지 직접 측정)
- **KR2:** 발행 글 중 카드뉴스가 `완료`·`경고` 상태인 비율 100% (`index.json` 기준)
- **KR3:** 문구 수정 1회 이하로 쓴 카드뉴스 비율 70% 이상 (게시 전 고친 카드 장 수를 직접 기록)

| API 요금                   | 관리자가 누를 때만 호출, 글 1편당 최대 2회, `effort: low`. 요금은 입력한 키의 계정에 청구 |
