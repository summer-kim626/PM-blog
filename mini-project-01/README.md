# Mini Project 01 — 블로그 AI 기능으로 워크플로우 자동화하기

> 내 블로그의 **독자** 또는 **관리자(나)**를 위한 AI 기능을 기획 → 디자인 → 개발까지 직접 구현하고,
> 출시·운영·마케팅까지 고려해 하나의 프로젝트를 처음부터 끝까지 완성한다.

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 목표 | 출시·운영·마케팅을 고려한 프로젝트를 처음부터 끝까지 설계하고 구현 |
| 주제 | 블로그 독자 또는 관리자(나)를 위한 AI 기능 구현(기획-디자인-개발)으로 워크플로우 자동화 |
| 대상 저장소 | [summer-kim626/PM-blog](https://github.com/summer-kim626/PM-blog) |
| 배포 블로그 URL | _TBD (배포 후 기입)_ |

## 2. 일정

| 날짜 | 내용 |
| --- | --- |
| 11/23 (월) | 공지 및 아이디에이션 |

| **11/25 (수) 16:50** | **최종 제출 마감** (GitHub 링크 + 결과보고서) |

> ⚠️ 11/25(수) 16:50 이후에는 새 커밋을 제출할 수 없다. 마지막 시간에는 학습조 회고가 있다.

## 3. 제출물

### 3-1. 최종 배포된 블로그 링크
- URL 형식으로 제출

### 3-2. GitHub 저장소 (1개)
중간 커밋 과정이 기록돼 있어야 한다. 아래 항목을 포함한다.

- [ ] PRD 기획서
- [ ] 소스코드
- [ ] 에이전트용 지침
- [ ] 성공/실패 로그
- [ ] 의사결정 로그
- [ ] 테스트 보고서

### 3-3. PRD 기획서 (2페이지 이하)
- **어떤 문제를 풀려고 하는지가 명확하게 정의**돼야 한다.
- `.md` 파일로 작성해 이 저장소에 추가한다.
- 버전별로 관리하거나, 업데이트 과정을 커밋 메시지로 남긴다.
- 참고 양식: [PRD 템플릿 (Google Docs)](https://docs.google.com/document/d/1G6Y4sBgrmhz9es0LJZ0pxihOaDvfI6cKZdgj9Zoounk/edit?tab=t.kn77c3ebzixi)

### 3-4. 테스트 보고서 (2페이지 이하)
- 전체 유저플로우 화면 스크린샷 포함
- 기능별 단위 테스트 포함
- `.md` 파일로 작성해 이 저장소에 추가한다.
- 버전별로 관리하거나, 업데이트 과정을 커밋 메시지로 남긴다.

## 4. 폴더 구조 (예정)

```
mini-project-01/
├── README.md              # 프로젝트 개요 (이 문서)
├── docs/
│   ├── PRD.md             # PRD 기획서 (2p 이하)
│   └── test-report.md     # 테스트 보고서 (2p 이하)
├── agent/
│   └── AGENTS.md          # 에이전트용 지침 (루트 CLAUDE.md가 불러옴)
├── logs/
│   ├── success-failure.md # 성공/실패 로그
│   └── decision-log.md    # 의사결정 로그
└── screenshots/           # 유저플로우 스크린샷
```

> 소스코드는 블로그 본체(`src/`, `index.html` 등)에 통합될 수 있으며, 변경 위치는 PRD와 의사결정 로그에 기록한다.

## 5. 진행 원칙

- 질문은 언제든 가능하다. 단, 피드백은 정답보다 **방향** 위주로 받는다.
- 중간 산출물을 요청받을 수 있으므로 작업 단위마다 커밋을 남긴다.
- 커밋 메시지에 PRD·테스트 보고서의 업데이트 과정이 드러나게 쓴다.
