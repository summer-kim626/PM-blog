## D-001. 프로젝트 주제 선정

- **날짜:** 2026-11-24
- **선택지**
  - A안 — 관리자용: 글을 올리면 AI가 요약하고 인스타그램 카드뉴스를 자동 생성
  - B안 — 독자용: 블로그 글 내용을 바탕으로 답하는 Q&A 챗봇
- **결정:** A안
- **이유**
  - 과제 목표인 "출시·운영·마케팅을 고려한 워크플로우 자동화"에 바로 맞는다.
  - 이미 동작하는 날씨 자동화와 같은 구조를 그대로 쓸 수 있어 이틀 안에 출시할 수 있다.
  - B안은 시연 효과가 크지만 서버리스 배포와 API 키 관리 리스크가 있다.
- **영향:** 1순위 고객이 관리자(나)가 된다. PRD 문제 정의를 "글 작성 후 홍보 작업" 중심으로 작성했다.

## D-002. AI 호출 위치

- **날짜:** 2026-11-24
- **선택지**
  - 브라우저(블로그 페이지)에서 직접 호출
  - 서버리스 함수(Vercel 등)
  - GitHub Actions
- **결정:** GitHub Actions
- **이유**
  - 블로그가 정적 사이트라 브라우저에서 호출하면 API 키가 그대로 노출된다.
  - Actions는 키를 Secrets에 보관하고, 결과 파일만 커밋할 수 있다.
  - 날씨 자동화(`.github/workflows/update-weather.yml`)로 이미 검증된 방식이다.
- **영향**
  - 카드뉴스는 실시간이 아니라 글 푸시 후 몇 분 안에 생성된다.
  - 날씨 봇이 1시간마다 커밋하므로 푸시 전 `git pull --rebase`가 필요하다.

## D-003. 인스타그램 자동 업로드 제외

- **날짜:** 2026-11-24
- **선택지**
  - 인스타그램 API로 자동 업로드까지 구현
  - 카드뉴스 생성까지만 자동화하고 업로드는 직접 진행
- **결정:** 업로드는 직접 진행 (MoSCoW의 Won't)
- **이유**
  - 자동 업로드에는 비즈니스 계정 전환과 API 앱 심사가 필요해 제출 기한(11/25 16:50) 안에 끝낼 수 없다.
  - 핵심 문제(홍보 콘텐츠 제작 시간)는 생성 자동화만으로 해결된다.
- **영향:** 블로그에 카드뉴스 미리보기·다운로드 기능(F6)을 두고, 업로드는 관리자가 직접 한다.
