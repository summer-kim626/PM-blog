## D-005. 카드 템플릿 구조와 위치

  - Canva·Figma 템플릿에 문구를 넣는다
  - 카드 장마다 HTML 파일을 따로 만든다
  - HTML 1장이 JSON을 읽어 카드 전부를 그리고, 헤드리스 브라우저로 카드별 캡처한다
- **결정:** HTML 1장 + JSON 입력, 위치는 루트 `cardnews/`
- **이유**
  - Canva·Figma는 Actions에서 자동으로 채우고 내보낼 수 없다.
  - AI 출력(JSON)이 그대로 입력이 되므로 F3과 F4 사이에 변환 단계가 없다.
  - 블로그와 같은 색 토큰·Pretendard 글꼴을 써서 블로그와 카드의 톤이 같다.
  - 같은 페이지를 `?scale=`로 축소하면 F6의 미리보기 화면으로도 쓸 수 있다.
- **영향**
  - 렌더러는 `?capture`로 열고 `window.__CARDS_READY`를 기다린 뒤 `.card`를 하나씩 캡처한다.
  - 글자 수 초과·넘침은 `window.__CARD_WARNINGS`로 확인한다. 테스트 보고서의 F4 항목에 쓴다.
  - 글꼴을 CDN에서 받으므로 캡처 환경에 인터넷 연결이 필요하다.

## D-006. 카드 도형을 넣는 방식

- **날짜:** 2026-11-24
- **배경:** 글만 있는 카드는 피드에서 눈에 띄지 않는다. 카드마다 내용을 한눈에 보여주는 간단한 선 도형을 넣기로 했다.
- **선택지**
  - AI가 카드마다 SVG 코드를 직접 생성한다
  - AI 이미지 생성 모델로 그림을 만든다
  - 미리 그린 도형 목록(`cardnews/figures.js`)에서 AI가 이름과 라벨만 고른다
- **결정:** 도형 목록에서 고르기 (14종)
- **이유**
  - AI가 SVG를 직접 그리면 모양이 깨지거나 매번 스타일이 달라지고, 코드가 페이지에 섞여 들어갈 위험이 있다.
  - 이미지 모델은 비용과 시간이 들고, 블로그 톤(선 2색)과 맞추기 어렵다.
  - 목록 방식은 결과가 항상 같은 스타일이고, 도형 이름이 틀려도 도형 없이 정상 렌더링된다.
- **영향**
  - AI 출력 JSON에 `figure: { shape, labels }`가 추가된다 (AGENTS.md 3-3).
  - 표현할 수 있는 그림은 14종으로 제한된다. 부족하면 도형을 추가한다.
  - 도형 이름 오류·라벨 6자 초과는 `window.__CARD_WARNINGS`에 기록된다.

## D-010. 관리자 페이지 다운로드 방식

- **날짜:** 2026-11-24
- **배경:** 관리자 페이지 표(PRD 4.3)는 글마다 다운로드 버튼이 하나다. 카드는 5~7장이라 한 번에 여러 파일을 받아야 한다.
- **선택지**
  - 버튼 하나로 PNG를 장별로 연달아 내려받는다
  - 카드 PNG 전 장 + 캡션을 ZIP 하나로 묶어 내려받는다
  - 워크플로우가 ZIP을 미리 만들어 커밋한다
- **결정:** 브라우저에서 ZIP 하나로 묶어 내려받는다 (`<slug>-cardnews.zip`)
- **이유**
  - 장별로 연달아 받으면 브라우저가 "여러 파일 다운로드 허용"을 물어 흐름이 끊긴다.
  - 업로드에 필요한 이미지와 캡션이 한 파일에 모여, 휴대폰으로 옮기기도 쉽다.
  - 워크플로우에서 ZIP을 만들면 PNG와 같은 내용이 저장소에 두 번 커밋된다.
- **영향**
  - ZIP에는 `card-NN.png` 전 장과 `caption.txt`(캡션·해시태그)를 넣는다.
  - 관리자 페이지에서 JSZip을 cdnjs로 불러온다(버전 고정).
  - 장별 PNG 저장은 미리보기 팝업에서 할 수 있다.
  - PRD 4.1 Could에 있던 ZIP 다운로드를 F7(Must)로 옮겼다.

## D-011. F2~F4 구현 방식과 소스 위치

- **날짜:** 2026-11-24
- **선택지**
  - Python 스크립트 + Playwright(브라우저 내려받기 포함)
  - Node 스크립트 + `playwright`(Chromium 내려받기 포함)
  - Node 스크립트 + `playwright-core` + 이미 설치된 Chrome
- **결정:** Node 스크립트 + `playwright-core`(1.49.1) + 설치된 Chrome, 위치는 `scripts/cardnews/`
- **이유**
  - 저장소에 이미 `package.json`이 있어 도구를 하나 더 늘리지 않는다.
  - `playwright-core`는 브라우저를 내려받지 않는다. 로컬 Mac과 GitHub Actions(ubuntu-latest) 모두 Chrome이 설치돼 있다.
  - F2(본문 추출)는 글 HTML 구조가 단순해 추가 라이브러리 없이 `<article>`만 잘라 처리한다.
  - Gemini는 SDK 없이 REST API를 `fetch`로 부른다. 키는 URL이 아닌 헤더(`x-goog-api-key`)로 보내 로그에 남지 않게 한다.
- **영향**
  - 실행: `npm run cardnews -- posts/<파일>.html`. `--skip-ai`는 AI 호출 없이 PNG만 다시 그린다(PRD Could 항목을 미리 확보).
  - 로컬 키는 `.env`(커밋 제외)에서 읽는다. Node 22 이상이 필요하다(`--env-file-if-exists`).
  - 템플릿이 `fetch`로 JSON을 읽기 때문에, 렌더러가 저장소 루트를 임시 HTTP 서버(127.0.0.1)로 띄운다.
  - 슬러그·제목·카테고리·생성 시각은 AI가 아니라 코드가 채운다. `summary.json`에 사용한 모델 이름(`model`)을 함께 남긴다.

## D-012. 대체 모델 추가

- **날짜:** 2026-11-24
- **배경:** `gemini-3.8-flash`가 503(과부하)을 자주 돌려주고, 응답해도 2분을 넘기는 경우가 있어 Actions 실행 #2가 실패했다.
- **선택지**
  - 3.8 Flash만 쓰고 재시도 횟수·대기 시간을 늘린다
  - 과부하·시간 초과일 때 2회차를 다른 모델로 보낸다
- **결정:** 2회차는 대체 모델로 보낸다. 대체 모델은 `gemini-3.5-flash-lite`
- **이유**
  - 과부하는 같은 모델로 다시 보내도 또 실패하기 쉽다. 모델마다 부하가 달라 다른 모델이 응답할 가능성이 높다.
  - 같은 키로 5개 모델에 짧은 요청을 보낸 결과, 그 시점에 정상 응답한 모델은 `gemini-3.5-flash-lite`뿐이었다(3.8·3.5 Flash는 503, `flash-latest`는 60초 무응답, 2.5 Flash는 종료됨).
  - 글 1편당 호출 최대 2회 규칙은 그대로 지킨다.
- **영향**
  - 어떤 모델로 만들었는지 `summary.json`의 `model`에 남는다. Lite 모델은 문구 품질이 낮을 수 있어 관리자 검토가 더 중요해진다.
  - 형식 오류(파싱·스키마)는 과부하가 아니므로 같은 모델로 재시도한다.
  - 응답 속도를 위해 추론 단계를 `thinkingLevel: "low"`로 낮췄다(`GEMINI_THINKING`).
  - 대체 모델도 과부하면 그 글은 실패로 기록되고, 관리자 페이지에서 재생성한다.
