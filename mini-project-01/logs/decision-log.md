## D-002. AI 호출 위치

- **날짜:** 2026-11-24
- **선택지**
  - 브라우저(블로그 페이지)에서 직접 호출
  - 서버리스 함수(Vercel 등)
  - GitHub Actions
- **결정:** GitHub Actions
- **이유**
  - 블로그가 정적 사이트라 브라우저에서 호출하면 API 키가 그대로 노출된다.
  - Actions는 키를 Secrets에 보관하고, 결과 파일만 커밋할 수 있다.
  - 날씨 자동화(`.github/workflows/update-weather.yml`)로 이미 검증된 방식이다.
- **영향**
  - 카드뉴스는 실시간이 아니라 글 푸시 후 몇 분 안에 생성된다.
  - 날씨 봇이 1시간마다 커밋하므로 푸시 전 `git pull --rebase`가 필요하다.

## D-005. 카드 템플릿 구조와 위치

- **날짜:** 2026-11-24
- **선택지**
  - Canva·Figma 템플릿에 문구를 넣는다
  - 카드 장마다 HTML 파일을 따로 만든다
  - HTML 1장이 JSON을 읽어 카드 전부를 그리고, 헤드리스 브라우저로 카드별 캡처한다
- **결정:** HTML 1장 + JSON 입력, 위치는 루트 `cardnews/`
- **이유**
  - Canva·Figma는 Actions에서 자동으로 채우고 내보낼 수 없다.
  - AI 출력(JSON)이 그대로 입력이 되므로 F3과 F4 사이에 변환 단계가 없다.
  - 블로그와 같은 색 토큰·Pretendard 글꼴을 써서 블로그와 카드의 톤이 같다.
  - 같은 페이지를 `?scale=`로 축소하면 F6의 미리보기 화면으로도 쓸 수 있다.
- **영향**
  - 렌더러는 `?capture`로 열고 `window.__CARDS_READY`를 기다린 뒤 `.card`를 하나씩 캡처한다.
  - 글자 수 초과·넘침은 `window.__CARD_WARNINGS`로 확인한다. 테스트 보고서의 F4 항목에 쓴다.
  - 글꼴을 CDN에서 받으므로 캡처 환경에 인터넷 연결이 필요하다.

## D-006. 카드 도형을 넣는 방식

- **날짜:** 2026-11-24
- **배경:** 글만 있는 카드는 피드에서 눈에 띄지 않는다. 카드마다 내용을 한눈에 보여주는 간단한 선 도형을 넣기로 했다.
- **선택지**
  - AI가 카드마다 SVG 코드를 직접 생성한다
  - AI 이미지 생성 모델로 그림을 만든다
  - 미리 그린 도형 목록(`cardnews/figures.js`)에서 AI가 이름과 라벨만 고른다
- **결정:** 도형 목록에서 고르기 (14종)
- **이유**
  - AI가 SVG를 직접 그리면 모양이 깨지거나 매번 스타일이 달라지고, 코드가 페이지에 섞여 들어갈 위험이 있다.
  - 이미지 모델은 비용과 시간이 들고, 블로그 톤(선 2색)과 맞추기 어렵다.
  - 목록 방식은 결과가 항상 같은 스타일이고, 도형 이름이 틀려도 도형 없이 정상 렌더링된다.
- **영향**
  - AI 출력 JSON에 `figure: { shape, labels }`가 추가된다 (AGENTS.md 3-3).
  - 표현할 수 있는 그림은 14종으로 제한된다. 부족하면 도형을 추가한다.
  - 도형 이름 오류·라벨 6자 초과는 `window.__CARD_WARNINGS`에 기록된다.
