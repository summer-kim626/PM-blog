## 2. F3 AI 생성 (키 없음)

## 3. F4 렌더링

- **시도:** `node scripts/cardnews/render.mjs cardnews/sample.json <임시 폴더>`, `npm run cardnews -- … --skip-ai`
- **결과:** 성공. PNG 6장, 각 1080×1350. 경고 0건. 처음 실행은 약 20초(Chrome 첫 실행), 다시 실행하면 약 4초.
- **확인:** 표지·핵심 카드를 눈으로 확인했다. 글꼴(Pretendard)과 도형이 정상 표시됐다.
- **다음 행동:** 실제 AI 결과로 다시 렌더링해 글자 넘침 경고가 나오는지 본다.

## 4. F3 실제 Gemini 호출

- **시도:** `.env`에 키를 넣고 `npm run cardnews -- posts/2026-11-18-start-pm-blog.html` 실행
- **결과:** 실패. `Gemini API 402: Your prepayment credits are depleted.` F2까지는 정상이었고, 파일은 만들어지지 않았다(실패 시 빈 결과를 남기지 않는 규칙대로 동작).
- **원인 확인**
  - 같은 키로 모델 목록 API(생성 아님, 비용 없음)를 부르니 200이 돌아왔다 → 키는 유효하다.
  - 목록에 `gemini-3.8-flash`가 있다 → 모델 ID도 맞다.
  - 402는 키가 속한 Google 프로젝트가 **선불 결제 프로젝트이고 크레딧이 0**이라는 뜻이다. 결제가 연결된 프로젝트는 무료 등급이 적용되지 않는다.
- **배운 점:** "무료 모델"이어도 키를 만든 프로젝트의 결제 설정에 따라 유료로 처리된다. 402는 4xx라 재시도하지 않고 바로 멈췄다(호출 1회).
- **다음 행동:** 결제가 연결되지 않은 프로젝트에서 새 키를 만들거나, 현재 프로젝트에 크레딧을 충전한다(관리자 결정).

## 5. 새 키로 F2~F4 전체 실행

- **시도:** 결제가 연결되지 않은 새 계정에서 키를 받아 `.env`를 바꾸고 `npm run cardnews -- posts/2026-11-18-start-pm-blog.html` 실행
- **결과:** 성공. 1회차는 `503 high demand`(모델 과부하)로 실패했고, 재시도한 2회차에서 생성됐다. 카드 6장, 경고 0건, PNG 넘침 0건. 전체 289초.
- **문구 검토**
  - 본문에 없는 사실·수치는 없었다.
  - 캡션 끝 "계속 배워나가는 과정을 담아가겠습니다"는 본문에 없는 다짐이 약간 덧붙었다.
  - 4번 카드 body "…한 글에 한 질문을 다룹니다"는 문장이 어색하다.
  - "진행 중인 기록" 카드에 `bulb`(아이디어)를 골랐는데 내용과 잘 맞지 않는다(`doc`이 더 맞음).
- **새로 발견한 문제:** 호출에 시간 제한이 없어 2회차 응답을 4분 넘게 기다렸고, 재시도도 기다림 없이 바로 보냈다.
- **다음 행동:** 호출 시간 제한 120초, 503·429·시간 초과일 때 15초 기다린 뒤 재시도하도록 고쳤다. Actions에서는 실행 시간이 길 수 있으므로 PRD의 "5분 이내" 기준을 지켜보며 조정한다.

## 6. F1·F5 워크플로우와 상태 기록

- **시도:** `.github/workflows/cardnews.yml` 작성, `run.mjs`에 `data/cardnews/index.json` 상태 기록 추가, 로컬에서 성공·실패를 한 번씩 실행
- **결과:** 성공. 성공한 글은 `done`, 없는 글은 `failed`와 오류 메시지가 기록됐다. YAML 문법 검사도 통과했다.
- **처음 결과의 문제:** 실패 메시지에 내 컴퓨터의 절대 경로(`/Users/…`)가 그대로 들어갔다. 이 파일은 공개 저장소에 커밋되므로 저장소 기준 상대 경로만 남기도록 고쳤다.
- **설계 메모**
  - F3는 성공했는데 F4가 실패하면 새로 쓴 `summary.json`을 이전 상태로 되돌린다(빈 결과·어긋난 결과를 남기지 않음).
  - 생성이 실패해도 `index.json`의 실패 상태는 커밋하고, 워크플로우는 마지막 단계에서 실패로 끝낸다.
  - 수동 실행의 slug 입력은 `YYYY-MM-DD-slug` 형식만 허용해 경로 조작을 막는다.
- **다음 행동:** 커밋·푸시 후 Actions 탭에서 수동 실행(`skip_ai`)으로 Chrome 렌더링과 봇 커밋을 먼저 확인하고, 이어서 AI 생성까지 확인한다.

## 7. Actions 수동 실행

- **시도 1 (실행 #1, `skip_ai`):** 성공. 26초. 봇이 `chore(cardnews): 2026-11-18-start-pm-blog 카드뉴스 생성`을 커밋했다. 러너(Ubuntu)의 Chrome으로 렌더링한 PNG에서 Pretendard 한글과 도형이 로컬과 같게 나왔다.
- **시도 2 (실행 #2, AI 포함):** 실패. 2분 25초. 1회차는 503(과부하)으로 바로 실패하고, 15초 뒤 2회차는 120초 안에 응답이 오지 않았다.
  - 실패 처리는 설계대로 동작했다: 이전 `summary.json`·PNG는 그대로 두고, `index.json`에 `failed`와 오류를 커밋(`… 카드뉴스 생성 실패 기록`)한 뒤 워크플로우를 실패로 끝냈다.
- **원인 분석:** `gemini-3.8-flash`가 과부하 상태이고, 응답할 때도 기본 "thinking"(추론) 때문에 느리다. 로컬에서도 응답에 4분 넘게 걸린 적이 있다.
- **시도 3 (로컬, thinking 낮춤):** `thinkingConfig.thinkingLevel: "low"`를 추가해 2번 호출했지만, 두 번 모두 1·2회차가 503으로 끝나 속도는 재지 못했다.
- **다음 행동:** 같은 모델만 기다리면 마감 전 안정적으로 돌지 않을 수 있다. 503·시간 초과일 때 다른 Flash 모델로 넘어가는 대체 모델을 둘지 결정이 필요하다(모델 변경은 관리자 결정).

## 8. 대체 모델 추가

- **시도 1:** 대체 모델을 `gemini-3.5-flash`로 두고 실행 → 3.8 Flash 503 → 3.5 Flash로 넘어갔지만 역시 503. 5초 만에 실패.
- **조사:** 같은 키로 5개 모델에 짧은 요청을 보냈다. 3.8·3.5 Flash는 503, `gemini-flash-latest`는 60초 무응답, `gemini-2.5-flash`는 404(종료된 모델), **`gemini-3.5-flash-lite`만 1.5초에 정상 응답**했다.
- **시도 2:** 대체 모델을 `gemini-3.5-flash-lite`로 바꿔 실행 → 3.8 Flash 120초 초과 → Lite로 넘어갔지만 이번엔 Lite도 503. 122초 만에 실패.
- **결과:** 대체 모델로 넘어가는 동작은 두 번 모두 의도대로 됐다. 실패한 실행은 `summary.json`을 건드리지 않았다. 생성 자체는 무료 등급 모델들이 동시에 과부하라 실패했다.
- **원인:** 외부 서비스(Gemini 무료 등급)의 일시적 과부하. 코드로 해결할 수 있는 문제가 아니다.
- **다음 행동:** 시간을 두고 다시 실행한다. 계속 실패하면 호출 횟수를 3회로 늘리거나(규칙 변경 필요) 유료 크레딧을 검토한다.
